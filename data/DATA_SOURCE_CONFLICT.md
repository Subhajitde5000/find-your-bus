# Data-source decision — the v2 workbook is now the source

Checked and decided 17 October 2026. This note records the measured conflict between the two
route workbooks and the decision that was taken: **the site now uses
`Kolkata_Comprehensive_Bus_Routes_and_Fleet_Directory-v2.xlsx` as its route source.** The old
`Kolkata_Comprehensive_Bus_Routes_and_Fleet_Directory.xlsx` is kept in the repository for
reference; the website no longer reads it.

## What changed

`fontend/src/data/kolkata-bus-data.json` is now generated by
`scripts/build_static_data.py` from:

1. `data/Kolkata_Comprehensive_Bus_Routes_and_Fleet_Directory-v2.xlsx`
2. `data/Kolkata_Bus_Stands_v2.xlsx`
3. `data/timetable_preview_routes.json` (sample routes only)

| | Old directory (previous site) | v2 (current site) |
|---|---|---|
| Route sheets | 466 | 75 |
| Routes in the bundled JSON | 460 directory + 8 sample = 468 | 75 directory + 8 sample = 83, plus 567 routes added later from the WBTC/Bus-O-Pedia lists (see `ROUTE_EXPANSION_AUDIT.md`) |
| Routes with timetable rows | 87 | 75 |
| Published runs | 1,048 paired round trips | 1,056 directional runs (528 outbound + 528 return); 1,058 after the one externally timed service |
| Intermediate-stop times | none — terminals only | **published at every stop column** |
| Stops in the bundled data | 388 | 152 |
| Route codes shared with the old directory | — | 69 |
| Codes only in v2 | — | 6: `5`, `15`, `Minibus_Garia`, `Digha_Express`, `Durgapur_Express`, `Siliguri_Express` |
| Old route sheets not in v2 | 397 (including 21 of the 87 timed routes) | — |

The 397 old-only routes are no longer shown. That is the accepted cost of using a 75-route
workbook whose timetables are complete: the old 460-route bundled directory (466 sheets, six of
them blank and replaced by samples) only had terminal times, and its middle-stop times were
estimated by the site. The v2 workbook carries a real passage time at every stop it lists, so the
site no longer needs to estimate anything for v2 routes.

## Why the two files cannot be merged

For the 69 shared route codes, the terminal times do not match, and every shared route has a
different run count. Pairing runs between the two files would be invented data. Some route
identities changed as well:

**C11**

- Old workbook (and the old site): `Howrah Railway Station` ↔ `Salt Lake Sector V`, 12 runs.
  Outbound `06:00 → 07:15`, return `07:30 → 08:45`, …
- v2: `Howrah Station` ↔ `Tollygunge Depot`, 7 runs.
  Outbound `06:15 → 07:10`, return `07:30 → 08:25`, …
- The site now shows the v2 C11: Howrah → B.B.D. Bagh → Esplanade → Hazra → Rashbehari →
  Charu Market → Tollygunge.

**S12**

- Old workbook: `Howrah Railway Station` → `Sapoorji / New Town`, via `Sealdah`, `Ultadanga`,
  `Karunamoyee`, `Salt Lake Sector V`.
- v2: `Howrah Bus Terminus` → `New Town Bus Stand`, timetable columns
  `Sealdah · Kankurgachi · Ultadanga / HUDCO · Karunamoyee · Eco Park · New Town`. There is **no
  `Salt Lake Sector V` column**, even though the sheet's distance-alignment sentence names
  Sector-V.

Other endpoint conflicts include `AC20`, `AC24`, `AC37`, `AC39`, `VS2`, `V1`, `S3A`, `S9`, `S31`,
`S32`, `C23`, `C28`, `NS1`–`NS4`, `44`, `45`, `80A`, `91`, `212`, `218`, `230`, `SD4`.

## Two v2 conventions that the build script had to define

### 1. The timetable columns are the stop list, not the alignment sentence

46 of the 75 v2 sheets have a distance-alignment sentence that differs from their timetable
header. S12 is the clearest example: the sentence includes `Rajabazar` and `Sector-V`, but the
timetable has no column for either. The script uses **only the timetable columns** as stops. The
alignment sentence is treated as a route description, not as a source of stops or times. Adding a
stop with no published time would put a place on the map without a time and would make the
interchange logic depend on prose.

Consequence for the reported journey: **no v2 route publishes a time at Salt Lake Sector V.** The
only remaining route that serves both Howrah Railway Station and Salt Lake Sector V is the retained
sample `S12E`, and every trip on that pair is labelled `Sample`. See
[`DIRECTION_BUG_AUDIT.md`](DIRECTION_BUG_AUDIT.md) for the measured result.

### 2. A sample route number that v2 owns is dropped

Route numbers must stay unique, so the old exporter rule still applies: when v2 publishes the same
number, the directory entry wins over the sample entry. Twelve of the twenty preview routes are
therefore skipped: `S5`, `AC5`, `AC6`, `5`, `S12`, `AC12`, `S24`, `AC9`, `AC4`, `S21`, `S4`, `AC1`.
The eight retained samples are `45B`, `46`, `AC9B`, `S12D`, `S12E`, `S14`, `S30`, `S6A`.

This changes which samples are kept compared with the old dataset: v2 owns route `5`, so the old
sample `5` is skipped; v2 has no `S14`, so the old dataset's skipped sample `S14` is now retained.
The **number** of sample routes is still 8, and all eight are labelled `Sample`.

## A separate accuracy question (still not attempted)

Published route lists also conflict with both workbooks. For example, the commonly published C11 is
`B.B.D. Bagh – Domjur`, with `C11/1` running `Howrah Station – Munshirhat`; neither workbook's C11
matches that. The user explicitly decided that the workbook is the project source and that no
published-source correction pass should be run. Conflicts are documented here; no value in either
workbook was changed.

Sources checked for the C11 example:

- Kolbusopedia government route list — https://www.kolbusopedia.com/bus-routes-government
- EverybodyWiki list of Howrah bus routes — https://en.everybodywiki.com/List_of_bus_routes_of_Howrah
- WBTC intra-city route list — https://wbtconline.in/assets/pdf/INTRA_CITY_RTS_Latest-small.pdf

## Reproducing the current data file

```bash
.venv/bin/python scripts/build_static_data.py
```

The script prints the route/run/stop counts, the number of blank time cells kept blank, the number
of midnight-crossing runs, and the sample routes that were superseded. It fails loudly if a sheet's
outbound and return stop sequences disagree, if a run has the wrong number of times, or if route
numbers/run codes are duplicated. It only reads the Excel files: **no cell in either workbook was
edited by this migration.**
